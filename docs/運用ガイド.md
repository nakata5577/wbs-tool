# 運用ガイド

WBS・マイルストーン管理ツール の運用者向け手順書。

> **対象読者**: 開発チーム（兼任運用担当）
> **前提**: デプロイ先は未確定（ローカル開発環境での手順を記載。デプロイ後に更新する）

---

## 1. 起動・停止手順

### 開発環境

**フロントエンド（Next.js）起動:**
```bash
cd frontend
npm run dev
# http://localhost:3000 で起動
```

**バックエンド（FastAPI）起動:**
```bash
cd backend
uv run uvicorn app.main:app --reload --port 8000
# http://localhost:8000 で起動
```

**停止:** ターミナルで `Ctrl+C`

### 本番環境

> デプロイ先が確定したらこの節を更新する。

候補デプロイ構成（要件定義書 §8.1 参照）:
- Vercel（フロント）+ Railway/Render（API）
- VPS 上の Docker Compose
- AWS（ECS + S3/CloudFront）

---

## 2. DB マイグレーション

### マイグレーションを適用する

```bash
cd backend
uv run alembic upgrade head
```

### マイグレーション履歴を確認する

```bash
cd backend
uv run alembic history
uv run alembic current
```

### 新しいマイグレーションを作成する（開発時）

```bash
cd backend
uv run alembic revision --autogenerate -m "add_xxx_column"
```

---

## 3. バックアップ

> デプロイ先が確定したら具体的な手順に更新する。

**対象ファイル**: `backend/data/app.db`（SQLite データベースファイル）

**暫定手順（ローカル）**:
```bash
cp backend/data/app.db backend/data/app.db.backup.$(date +%Y%m%d_%H%M%S)
```

**本番環境での方針**:
- デプロイ先確定後に RPO/RTO を決定する（要件定義書 §5.5）
- 定期バックアップ（cron 等）で SQLite ファイルを別ストレージにコピー
- バックアップ世代数・保持期間はデプロイ先のストレージコストに応じて決定

### リストア手順

```bash
# バックアップから復元（サービス停止後に実施）
cp backend/data/app.db.backup.YYYYMMDD_HHMMSS backend/data/app.db
# サービスを再起動して動作確認
```

## 4. ヘルスチェック

```bash
curl http://localhost:8000/health
# 正常: {"status": "ok"}
```

本番環境では監視ツール（UptimeRobot 等）からこのエンドポイントを定期的に叩いて死活監視する。

---

## 5. ログ確認

**バックエンドログ（ローカル）**: `uv run uvicorn` の標準出力に出力される。

**エラーログの確認方法（本番）**: デプロイ先のログ基盤に応じて確認する（CloudWatch Logs / Railway ログ等）。

---

## 6. 設定変更

**環境変数**: `backend/.env` または環境変数で設定（`.env.example` を参照）。

| 変数名 | 説明 | デフォルト |
|-------|------|---------|
| `DATABASE_URL` | SQLite の接続先 | `sqlite:///./data/app.db` |
| `CORS_ORIGINS` | 許可するオリジン | `http://localhost:3000` |

**フロントエンド環境変数**: `frontend/.env.local` で設定。

| 変数名 | 説明 |
|-------|------|
| `NEXT_PUBLIC_API_URL` | バックエンド API の URL |

## 7. 障害時の初動対応

### 7.1 サービスが応答しない

1. ヘルスチェックで死活確認: `curl http://<HOST>/health`
2. プロセスが停止していれば再起動
3. エラーログを確認して原因を特定
4. 解決しない場合は incident を起票（`.github/ISSUE_TEMPLATE/incident.md`）

### 7.2 DB エラーが発生している

1. `backend/data/app.db` の存在とパーミッションを確認
2. マイグレーションの適用状況を確認: `uv run alembic current`
3. バックアップから復元が必要な場合は「3. バックアップ」のリストア手順を実施

### 7.3 フロントエンドが表示されない

1. フロントエンドのビルドエラーを確認
2. `NEXT_PUBLIC_API_URL` が正しいバックエンド URL を指しているか確認
3. CORS エラーの場合は `CORS_ORIGINS` の設定を確認

## 8. 依存関係の更新・脆弱性チェック

```bash
# フロントエンド
cd frontend && npm audit
cd frontend && npm update

# バックエンド
cd backend && uv run pip-audit
cd backend && uv sync --upgrade
```

セキュリティ上の重大な脆弱性が発見された場合は即時対応する（`.claude/rules/operations.md` 参照）。
