# 横断的関心事設計

## 責務

プロジェクト全体に共通するエラーハンドリング・ログ設計・タイムゾーン・バリデーション・セキュリティ方針を定義する。各領域の設計書はここを参照し、横断的な内容の重複定義を避ける。

## エラーハンドリング

### バックエンド（FastAPI）

| ケース | HTTP ステータス | レスポンス形式 |
|-------|-------------|------------|
| バリデーションエラー | 422 | Pydantic デフォルト（FastAPI 標準） |
| リソース未存在 | 404 | `{ "detail": "Not found" }` |
| 内部エラー | 500 | `{ "detail": "Internal server error" }` |

- グローバル例外ハンドラー（`@app.exception_handler`）でスタックトレースをログに出力し、クライアントには内部情報を返さない。

### フロントエンド（Next.js）

- API エラーは `try-catch` で捕捉し、`role="alert"` の要素でユーザーに通知
- ネットワークエラー（fetch 失敗）は「再試行」ボタンを表示
- 楽観的更新（Optimistic UI）は採用しない（シンプルさ優先）
- Error Boundary（`error.tsx`）で予期しない React エラーをキャッチし、フォールバック UI を表示

## ログ設計

| 層 | 手段 | レベル |
|----|------|-------|
| バックエンド | FastAPI `logging` モジュール（標準出力） | INFO 以上（エラーはスタックトレース付き） |
| フロントエンド | `console.error` のみ（外部ログ基盤は初期未導入） | エラーのみ |

- 個人情報（担当者名）をログに出力しない（担当者名はフリーテキストのため注意が必要）

## タイムゾーン

| 対象 | 方針 |
|------|------|
| タイムゾーン固定 | JST（UTC+9）のみ。多言語・多タイムゾーン対応なし |
| DB 保存 | `DATETIME` カラムは UTC で保存（`datetime('now')` = UTC） |
| フロント表示 | UTC → JST 変換（`toLocaleString('ja-JP', { timeZone: 'Asia/Tokyo' })`） |
| 日付のみのフィールド | `DATE` 型（start_date / end_date / milestone.date）はタイムゾーン変換不要 |
| 日付フォーマット | YYYY-MM-DD（API） / YYYY年MM月DD日（UI 表示） |

## 入力バリデーション

| 層 | 手段 | タイミング |
|----|------|----------|
| フロントエンド | React Hook Form + Zod | フォーム送信前（UX 向上） |
| バックエンド | Pydantic スキーマ | API 受信時（セキュリティ保証） |

- フロントのバリデーション通過後もバック側で再検証する（クライアント迂回を考慮）
- SQL インジェクション対策: SQLAlchemy ORM のパラメータバインディングに委ねる（生 SQL は使わない）
- XSS 対策: React の JSX は自動エスケープ。サーバーサイドでの HTML 生成は行わない

## セキュリティ

- **CORS**: FastAPI の `CORSMiddleware` でフロントエンドオリジンのみ許可（`localhost:3000` / 本番 URL）
- **認証**: なし（社内ネットワーク/VPN によるアクセス制御）
- **依存脆弱性**: `npm audit`（フロント）・`pip-audit`（バック）で定期チェック

## 主要な設計判断

- **楽観的更新を採用しない**: 実装シンプルさ優先。保存完了後にサーバーレスポンスで状態を更新する。
- **二重バリデーション**: フロント（UX）とバック（セキュリティ）の両方でバリデーションを実施する。重複に見えるが役割が異なる。
- **外部監視 SaaS は初期未導入**: 小規模社内ツールのため `console.log` と FastAPI 標準ログで十分と判断。運用中に問題が出れば Sentry 等を追加検討。
